# 결혼식 입력 폼 구조 문서 (고정본 v1)

- Version: v1
- 작성일: 2026-01-23
- Applies to: wedding invitations only
- Template baseline: wedding_classic

## 목적
결혼식 초대장을 만들기 위해 사용자가 어떤 순서로 무엇을 입력하는지 명확히 정의한다.
디자인이 달라져도 입력 구조와 데이터 흐름은 이 문서를 기준으로 유지한다.
이 문서는 팀/디자이너/개발 공통 기준이며, 이후 변경은 문서와 스키마에서만 수행한다.

## 입력 단계 전체 플로우 (0~9)
0. 기본 설정
1. 대표 정보
2. 대표 이미지
3. 초대 문구
4. 신랑 / 신부
5. 갤러리
6. 위치
7. 계좌
8. 부가 기능
9. 공유 미리보기

## STEP 0. 기본 설정
### 목적
결혼식 초대장의 종류/템플릿/언어를 최초 1회 확정한다.

### 필수 입력
- 초대장 타입: 결혼식 (고정)
- 템플릿: wedding_classic (고정)
- 언어 선택

### 선택 입력
- 없음

### UX 규칙
- 최초 1회만 입력한다.
- 이후 단계에서 수정/변경 UI를 제공하지 않는다.

## STEP 1. 대표 정보
### 목적
초대장의 기본 정보(제목/일시/장소)를 정의한다.

### 필수 입력
- 제목
- 예식 날짜
- 예식 시간
- 장소명

### 선택 입력
- 부제
- 홀 이름

### UX 규칙
- 상단 미리보기에 즉시 반영한다.

## STEP 2. 대표 이미지 (썸네일)
### 목적
공유 썸네일로 사용될 대표 이미지를 확정한다.

### 필수 입력
- 이미지 1장 업로드

### 선택 입력
- 없음

### UX 규칙
- 크롭/미리보기 제공
- "공유 시 이 이미지가 사용됩니다" 안내 문구는 고정 노출한다.

## STEP 3. 초대 문구
### 목적
초대장의 인사 문구와 본문 내용을 구성한다.

### 필수 입력
- 없음

### 선택 입력
- 인용 문구
- 본문 문단 (2~4개 권장)

### UX 규칙
- 문단 추가/삭제 가능

## STEP 4. 신랑 / 신부 정보
### 목적
신랑/신부의 기본 정보를 대칭 구조로 입력한다.

### 필수 입력
- 신랑 이름
- 신부 이름

### 선택 입력
- 신랑 사진
- 신부 사진
- 신랑 연락처
- 신부 연락처
- 신랑 부모 안내 문구
- 신부 부모 안내 문구

### UX 규칙
- 항상 2컬럼(신랑/신부) 대칭 구조를 유지한다.
- 모바일/PC 모두 가로 2컬럼 기준으로 설계한다.

## STEP 5. 갤러리
### 목적
초대장에 표시될 사진을 정렬된 순서로 구성한다.

### 필수 입력
- 없음

### 선택 입력
- 다중 이미지 업로드

### UX 규칙
- 순서 변경 가능
- 삭제 가능
- 초대장 표시 순서는 입력 순서를 그대로 따른다.

## STEP 6. 위치 안내
### 목적
예식 위치 및 이동 정보를 제공한다.

### 필수 입력
- 주소

### 선택 입력
- 교통 안내
- 주차 안내

### UX 규칙
- 지도 미리보기를 제공한다.

## STEP 7. 계좌 정보
### 목적
복수 계좌 정보를 표준 형식으로 입력한다.

### 필수 입력
- 계좌 추가 버튼
- 각 계좌: 구분(신랑/신부/부모), 은행명, 계좌번호, 예금주

### 선택 입력
- 없음

### UX 규칙
- 복수 계좌 가능
- 계좌 단위로 추가/삭제 가능

## STEP 8. 부가 기능
### 목적
참석 여부/방명록 노출 여부를 제어한다.

### 필수 입력
- 없음

### 선택 입력
- 참석 여부 (ON/OFF)
- 방명록 (ON/OFF)

### UX 규칙
- OFF 시 관련 UI/데이터를 노출하지 않는다.

## STEP 9. 공유 미리보기
### 목적
실제 초대장과 공유 썸네일/문구를 최종 확인한다.

### 필수 입력
- 없음

### 선택 입력
- 없음

### UX 규칙
- 실제 초대장 전체 미리보기 제공
- 공유 썸네일/문구 확인 가능
- 각 STEP으로 바로 이동 가능

## 모바일/PC 공통 규칙(반응형 기준)
- 입력 구조와 단계 순서는 동일하게 유지한다.
- 레이아웃 변화는 여백/폰트/정렬 수준으로 제한한다.
- STEP 4 신랑/신부는 모바일에서도 2컬럼 대칭 구조를 유지한다.

## "초대장에 보이는 순서 ≠ 입력 순서" 원칙
입력 단계는 사용자 입력 흐름을 위한 순서이며, 초대장 화면의 섹션 순서는 템플릿 디자인 기준을 따른다.
UI에서 입력 순서를 초대장 노출 순서로 강제 변환하지 않는다.

## 섹션 ON/OFF 정책(Extras)
- 참석 여부/방명록은 ON/OFF 설정만 제공한다.
- OFF일 경우 관련 UI와 데이터는 저장/노출하지 않는다.

## 공유 미리보기(OG) 확인 항목
- OG 썸네일: STEP 2 대표 이미지
- OG 제목: STEP 1 제목
- OG 설명: STEP 1 부제 또는 예식 날짜/장소 조합
- 언어 설정이 OG 텍스트에 일관되게 반영되어야 한다.

## 변경 시 원칙(문서+스키마만 수정)
- 변경은 반드시 이 문서와 스키마에서만 수행한다.
- UI/템플릿은 문서를 그대로 구현하며 역으로 구조를 변경하지 않는다.
- 변경 시 버전과 작성일을 갱신한다.

## 결론
이 문서는 결혼식 입력 폼의 헌법이며, 팀/디자이너/개발자 모두 이 기준을 따른다.
구조는 흔들리지 않으며, 변경은 문서와 스키마에서만 관리한다.
